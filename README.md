## 🚀 Instructions to Reproduce the Workflow

1. Install all project dependencies
```bash
pip install -r requirements.txt
```
2. Run all Jupyter notebooks in the scripts folder, following the numerical order in their filenames.

   ## 1.0.5-data-collection-steam-incremental(optional).ipynb
   
   This notebook is optional and is used for incremental refreshes of Steam data.

   Since a full Steam data download requires a long time, this workflow provides a faster alternative. The script compares the newly downloaded steam_spy_id_name list with the existing one, identifies only the new or changed AppIDs, and produces an incremental list.

   You may then jump directly to 1.1-data-collection-steam.ipynb and download only the new entries rather than reloading the entire dataset from the Steam Store API.
   
   ## 1.1-data-collection-steam.ipynb

   This script contains 3 files output:
   
   - **steam_app_data.csv** 
   - **steam_spy_all_data.csv** 
   - **steam_spy_id_name.csv** 

   The collection dependency is
   
   - steam_spy_all_data.csv -> steam_spy_id_name.csv -> steam_app_data.csv.
   
   Two Steam APIs are used:

      - **SteamSpy API** to retrieve the full list of games and metadata.

      - **Steam App API** to fetch additional fields for each AppID.

   We first query SteamSpy to obtain the ID–name pairs and then use those AppIDs to request detailed metadata from the Steam App API.

   Fetching all steam_app_data.csv records takes 10+ hours, due to deliberate pauses inserted between each request to avoid hitting rate limits.

   A steam_index.txt file is used to keep track of progress, enabling the notebook to resume safely after interruptions and to retry failed requests automatically.

   ### Ethics / Legal Constraints

   SteamSpy: Licensed for non-commercial use; bulk redistribution is discouraged.
This project does not redistribute the full SteamSpy dataset. Instead, it provides code for users to reproduce the data and includes only a minimal id_name subset.

   Steam Web API: Only public endpoints are used, with polite crawling and rate-limit delays.

   (Documentations: https://steamspy.com/api.php, https://medium.com/codex/scraping-information-of-all-games-from-steam-with-python)

   ## 1.2-data-collection-epic.ipynb

   This notebook retrieves the full Epic Games Store catalog and saves it to a JSON file. The fetching process typically finishes within a few minutes.

   Documentation: https://epicstore-api.readthedocs.io

   ### Ethics / Legal Constraints

   The API used is an unofficial free-to-use endpoint. To comply with redistribution rules, the repository includes only sample bronze-layer JSON for format validation. All real Epic data must be regenerated by users, and only the transformed Silver-layer outputs are retained in the project.

   ## 1.3-data-collection-igdb.ipynb

   To run this script, you need to get your api ID and secret from igdb api. The instruction is here: https://api-docs.igdb.com/#getting-started
   
   Then, use your own credential to fill CLIENT_ID and CLIENT_SECRET. You can also change the start and end time to set up the range of data.
   
   ```python
   start = int(dt.datetime(2015,1,1).timestamp())
   end   = int(dt.datetime(2025,12,31,23,59,59).timestamp())
     ```

   ### Ethics/legal constraints

   IGDB provides data under terms that prohibit direct redistribution. For this reason, the repository includes scripts only, not raw IGDB output. We only provide bronze layer sample data for format check use. 


   ## 1.4-bronze-data-EDA.ipynb

   This is the Exploratory Data Analysis for bronze layer data we just collected from steam, epic and igdb. It's optional in the whole workflow and shows the raw schema for the bronze layer.

   ## 2.1-steam_data_clean.ipynb, 2.2-epic_data_clean.ipynb, 2.3-igdb-data-clean.ipynb

   The 3 cleaning scripts flatten the nested JSON and remove the unused columns and out-of-scope time range data from bronze layer data. You can follow the script one by one or modifying the script to add any columns you want to keep.

   ## 2.4-descriptive-statistics.ipynb

   This script is running some data quality checks to compare pre-2015 and post-2025 data.

   ## 3.1-unify-gold-layer.ipynb

   This script integrates all silver layer data to one file.

   ## 3.2-indie-game-split.ipynb

   This script split the indie/non indie game from the file we deduced from 3.1.

   ## 3.3-indie-game-analysis-price.ipynb, 3.4-indie-game-analysis-platform.ipynb, 3.5-indie-game-analysis-genre.ipynb, 3.6-indie-game-analysis-publisher.ipynb, 3.7-indie-game-analysis-trend.ipynb

   The example analysis for the data we get above.
   
   Price Analysis:
   
    Compare price distributions across platforms, examine discount depth/frequency, and contrast indie vs. non-indie pricing behavior.


   Platform Analysis:
   
    Explore differences in market coverage (Steam/Epic/IGDB), exclusivity, and platform-specific characteristics such as popularity indicators, categories, and review volumes.


   Genre Analysis:
   
    Clean and standardize noisy genre labels, compute genre frequencies, and investigate which genres dominate indie vs. mainstream titles.


   Publisher Analysis:
   
    Identify top indie publishers, analyze publisher specialization, pricing strategies, and evaluate cross-platform presence.


   Trend Analysis:
   
    Use effective_date fields to study temporal patterns in releases, pricing, discounting, and shifting genre popularity over time.
